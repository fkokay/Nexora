# Nexora release go/no-go — 2026-10-26

**Karar: NO-GO — kalıcı remote deployment, migration ve promotion bekletilsin.** Asenkron tenant provisioning API → kuyruk → Worker mutlu yolu, transient Vault failure sonrası retry, expired-lease reclaim, iki tenant için ERP ve Studio SQL/Vault izolasyonu ve geçici anahtarla gerçek signed JWT üretim/doğrulama/yönlendirme yolu geçici remote kabul ortamında doğrulandı. Uygulama yeni tenant’lar için ayrı ERP/Studio veritabanlarını oluşturup şemalarını migrate edebiliyor; bu kanıt disposable hedeftedir. Üretim JWT imza anahtarı ve API host yapılandırması, Vault/SQL secret’ları ve DBA’nın en az yetki onayı, eski paylaşımlı Studio verisinin tenant DB’lerine kopyalanması ve geri yükleme kabulü, persistent hedef migration/backup kabulü, değişmez aday paket ve GitHub anahtar rotasyonu tamamlanmadı. Mevcut remote servislerin sağlıklı olması, çalışan sürümün bu değişiklikleri içerdiğini göstermez.

## Ayrı bekleyen aksiyonlar

- **Release / platform sahibi:** staging hedefi, commit-paket kimliği, change window, secret-store ve güvenli teslim sahiplerini atayıp immutable aday/provenance ve ikinci operatör incelemesini tamamlasın. Hata retry/lease expiry, signed production JWT, legacy Studio DB copy/restore, retention, rotation/restore ve outage kabulini tamamlayıp onaylasın.
- **GitHub App sahibi / güvenlik-operasyon:** yeni private key’i onaylı secret store üzerinden teslim etsin; runtime’ın replacement kullandığını doğrulasın ve eski anahtarı revoke/silsin. Yalnız redakte rotasyon zamanı ve operatör kanıtı kaydedilsin.
- **DBA + uygulama sahibi:** bu turdaki iki tenant SQL/Vault izolasyon kabulini temel alarak provisioning SQL kimliğinin minimum izinlerini yazılı olarak onaylasın; production Vault policy kapsamını doğrulasın. HTTP routing kabulini ve tenant başına migration hedef geçmişi, checksum yedek/restore provasını, nakit bütçesi migration’ının rol/custom-grant etkisini inceleyip yazılı onaylasın.
- **Ürün/izin sahibi:** `TenantUser` salt-okunur varsayılanı ve mevcut özel izinlerin korunması için staging kabul sonuçlarını onaylasın; `Down` davranışını rollback olarak saymasın.
