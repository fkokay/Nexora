# AI ERP Assistant data access

The ERP Assistant handles tenant data through an explicit, request-scoped sharing choice. The UI checkbox is unchecked until the user confirms it, and the AI Service rejects requests without `AISharingConfirmed` before it resolves a provider or sends a request. The choice applies to that chat request; it is not a saved tenant-wide consent setting. The assistant audit event records only the action and a fixed resource label, never the question, history, or returned records.

When consent is present, the assistant sends the question and up to ten user/assistant history turns to the selected provider. Email addresses, IBANs, phone numbers and long numeric identifiers are redacted from that text first. The user should still avoid entering confidential details that are not needed to answer the question.

ERP reads use named, parameter-validated tools. No SQL text is accepted, and the tool registry only exposes allowlisted read paths. The assistant can search sales orders with a required 2–100 character term; it requests only page 1 with at most ten rows and returns order code, customer, date and status. It can search purchase orders with the same bounded term and page size, returning only order code, supplier, date and status. The AI Service forwards the caller's bearer token to the Platform API, so normal tenant selection, route/module authorization and tenant database routing still run. Record-level restrictions are enforced where the underlying endpoint or report source implements them; they are not a universal filter across every report source. For example, sales-order and purchase-order lists and purchase-request reports apply their record-level filters, while assistant report access adds a source-level module permission check because the report builder's `erp.reports.read` permission alone is broader than the report's underlying ERP area. Transaction reports require a source date window no wider than 365 days; report output is limited to ten rows and bounded columns/text. A downstream 403 produces a safe access-denied answer with an opaque request reference; the server response body is not shown to the user.

The assistant does not expose HR or payroll report sources. Customer, supplier, financial, and other sensitive business data are available only through their relevant existing module permission and any existing row restrictions. The assistant does not read platform secrets, provider credentials, or another tenant's database. There are no write or raw-query tools.

Tests for the permission mapping, bounded date windows, and prompt redaction are in `ERPAssistantReportAccessTests`. Live provider credentials and live AI quality evaluation are not required for these checks.
