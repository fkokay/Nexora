# MRP II finite-capacity staging operator checklist

**Purpose:** operator-facing preparation and sign-off for the [synthetic acceptance fixture](fixtures/mrp-ii-finite-capacity-acceptance-20261026.md). This checklist documents the current UI/API path and expected evidence; it does not authorize production data or replace the fixture's synthetic setup. No scenario has been run.

## Before the window

- [ ] Use an isolated staging tenant and warehouse with synthetic records only; assign fresh IDs and ensure no other stock, demand, receipts, reservations, orders, or allocations can affect the case.
- [ ] Freeze UTC at **2026-10-26** for the scheduler. The MRP API accepts `planDate`; the current UI does not expose it and sends no `planDate`, so use the API with `planDate: "2026-10-26"` or a staging clock frozen to that date. The scheduler itself uses the live UTC date as its lower bound.
- [ ] Confirm Manufacturing has approved the fixed date, local-minute interpretation, and precondition that 19 SA-200 units are available before scheduling the finished-good order. The scheduler schedules one order at a time and does not enforce cross-order BOM dependencies.
- [ ] Confirm access to **Manufacturing** and any approved API client. Relevant UI areas are **Material requirements plan**, **Manufacturing orders**, and each work center's calendar/setup-rule panels.

## Sign-off and decision gates

| Role | Sign-off |
|---|---|
| Manufacturing / production owner | Approves synthetic data, calendar and local-minute interpretation, 19-unit subassembly availability precondition, expected MRP rows, routing, capacity allocation, and whether to include the separate blocked control. |
| Product owner | Approves that current behavior is being accepted within scope: one-order-at-a-time scheduling, no cross-order pegging/dependency enforcement, and no sub-minute placement. Sector/plant holiday calendars and general inter-order dependency behavior remain product decisions, not assertions in this fixture. |
| HR | No HR decision is needed for this fixture because zero labor rates are specified and labor cost is explicitly not an acceptance output. Any future employee-time/payroll cost assertion needs HR policy and privacy/access decisions. |
| Finance | No finance decision is needed for this fixture because costs are explicitly excluded. Any future labor/overhead valuation, inventory costing, or GL reconciliation assertion needs finance policy and sign-off. |
| Staging operator | Records plan/order IDs, frozen-clock method, API request/response captures, calendar/setup snapshots, schedule allocation evidence, errors (if any), and all role sign-offs. |

**Decision-needed cases:** Manufacturing must approve the test anchor/calendar interpretation and subassembly availability precondition before execution. Product must decide whether the extra blocked control is in scope and how to treat cross-order dependencies, sector calendars, or sub-minute precision if acceptance is expanded. HR and Finance are not gates for this zero-cost fixture; they become gates only if employee cost, valuation, or ledger assertions are added.
